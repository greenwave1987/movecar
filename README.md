# 🚗 挪车通知系统（MoveCar Notify）

基于 **Cloudflare Workers + Cloudflare KV** 的轻量级网页挪车通知系统。申请者拍摄**车头 + 车尾**两张现场照片后一键通知车主，支持企业微信 / Bark 多通道推送、车主多条记录选择回复、等待页轮询车主回复、"车主要求重拍"闭环流程、历史记录分页查看，以及在特定未回复条件下自动解锁拨号按钮。

## 🧪 本地 / GitHub Pages 模拟测试

`index.html` 提供了纯前端模拟测试页（数据存 localStorage，无后端），可体验与线上 Worker 完全一致的交互逻辑：申请提交（车头/车尾双照片）、记录展示与刷新分页、一键通知 60 秒锁定、再次通知 30 秒冷却、车主回复专注展示、重拍流程与电话按钮解锁。

- **在线模拟测试页**：[点击打开 GitHub Pages 模拟测试页](https://greenwave1987.github.io/movecar)
- 模拟车主页：在页面顶部切换，或在申请页链接后加 `?view=owner`

## ✨ 核心功能

- **车头 + 车尾双照片上传**：提交挪车申请时必须分别拍摄车头、车尾两张现场照片（支持移动端相机拍摄或相册选择）。前端 Canvas 压缩为两档：原图最长边 1600px / 质量 0.75（存 KV 供放大查看），缩略图 320px / 质量 0.6（随记录存 KV 供列表展示，大幅减小接口流量）；服务端兜底单张原图最大 15MB。
- **多通道推送**：提交后同时通过 **企业微信应用消息**（文本 + 车头/车尾两张图片，图片走临时素材 `media_id` 上传）与 **Bark**（`level=critical`，可设置提醒铃声与跳转链接）推送，附带车主确认页链接（`/owner-confirm?id=...`）。
- **车主多记录选择与快捷回复**：车主打开确认页可查看当日申请列表（每次展开 3 条，可手动刷新 🔄），点击切换对应申请，查看留言与车头/车尾两张照片（点击可全屏放大，缩略图秒开、原图按需加载），发送快捷回复（`马上`、`重拍`、`拒绝`）或自定义回复。
- **申请页状态轮询与操作**：
  - 发送成功后进入等待页，每 3 秒轮询 `/api/check-status`（最长约 6 分钟），收到回复后震动提醒并展示回复内容。
  - 操作区包含 **再次通知**（间隔 30 秒冷却，刷新页面不失效）与 **返回申请页**（清理轮询定时器并刷新今日记录），满足条件后显示 **直接打电话** 按钮。
- **一键通知防重复**：最新一条记录发出后 **60 秒内**锁定"一键通知车主"按钮并倒计时（按记录时间计算，刷新页面也不失效）；例外：最新记录的回复是"车主要求重拍"类时按钮不锁定，可直接再次通知。
- **车主要求重拍闭环**：车主回复"重拍"（含 `换个角度` / `重新拍摄`）后，申请页清空已选照片、显示重新拍摄上传区，"再次通知"按钮变为"重新拍照并通知车主"，未重新上传两张照片不允许再次通知；其他类型回复则隐藏"再次通知"入口，避免重复催促。
- **车主最新回复专注展示**：车主回复后 **5 分钟内**，申请页记录列表只专注展示这条最新回复（含回复时间），到期自动恢复完整列表。
- **电话按钮自动解锁规则**：
  - 当日累计收到 **≥ 3 条** 未回复申请；
  - 且 **最近连续 3 条** 均未回复；
  - 且这连续 3 条中 **第 1 条（最早）与第 3 条（最新）时间间隔超过 1 分钟**（`> 60000ms`）；
  - 满足上述条件时自动显示"直接打电话"按钮（连续点击 3 次"再次通知"也可手动解锁）。
- **仅电话模式**：只配置了 `PHONE_NUMBER` 而未配置任何通知通道时，申请页顶部直接显示"电话联系车主"拨号卡片。
- **防刷与容量控制**：通知接口按 IP 限流（每 60 秒最多 5 次）；当日记录超过 `MAX_RECORDS` 条时自动丢弃最旧记录；所有 KV 数据 24 小时自动过期（次日自动清理）。

## 🚀 快速部署（Cloudflare Workers）

1. 在 Cloudflare Dashboard 创建 **KV Namespace**，并在 Worker 绑定中命名为 `MOVE_CAR_STATUS`。
2. 将 `worker.js` 部署到 Cloudflare Worker。
3. 可选配置环境变量 / Secrets：
   - `PHONE_NUMBER`：车主联系电话（用于 `tel:` 拨号按钮；**若仅设置了 `PHONE_NUMBER` 而未配置通知通道，申请页会直接显示"电话联系车主"按钮**）
   - `QYWX_AM`：企业微信应用配置，格式为 `corpid,corpsecret,agentid[,touser]`（支持中英文逗号分隔；`touser` 可选，默认 `@all`，多用户用 `&` 分隔，例如 `ww123,secret123,1000002,user1&user2`）。也兼容旧的独立变量写法 `WECOM_CORPID` / `WECOM_APP_SECRET` / `WECOM_AGENTID` / `WECOM_TOUSER`
   - `BARK_URL`（可选，Bark 推送服务地址，例如 `https://api.day.app`）
   - `ACCESS_PIN`（可选，车主确认页访问口令；设置后车主回复需先输入正确口令，口令错误返回 403 并弹出输入框，输入后自动重试，正确口令会缓存在浏览器 localStorage）
   - `MAX_RECORDS`（可选，当日最多保留的挪车记录条数，默认 10）

## 📡 API 一览

| 接口                             | 方法   | 说明                                                                                     |
| ------------------------------ | ---- | -------------------------------------------------------------------------------------- |
| `/api/notify`                  | POST | 提交挪车申请，`multipart/form-data`：`message`、`image1/thumb1`（车头）、`image2/thumb2`（车尾），按 IP 限流 |
| `/api/owner-confirm`           | POST | 车主回复，JSON：`recordId`、`reply`、`pin`（设置了 `ACCESS_PIN` 时必传）                               |
| `/api/check-status`            | GET  | 等待页轮询：返回 `{ status, reply }`                                                           |
| `/api/get-today-records`       | GET  | 当日记录列表（含 `pinRequired` 标记）                                                             |
| `/api/get-photo?id=...&n=1\|2` | GET  | 按记录 ID 查看原图，`n=1` 车头、`n=2` 车尾（旧单图记录任意 n 返回那张）                                          |
| `/api/get-car-data`            | GET  | 返回最新通知的留言与照片（兼容旧前端）                                                                    |
| `/api/debug-wecom`             | GET  | 排查企业微信图片推送：返回最近一次素材上传与发送结果                                                             |
| `/owner-confirm`               | GET  | 车主确认与回复页面                                                                              |
